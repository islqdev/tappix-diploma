# Ерсұлтану — как проверить материалы

Войди в GitHub под своим аккаунтом `Ersultan7`. Пароль никому передавать не нужно.
Проверка означает прочитать и понять материалы, а не просто нажать кнопку.

## Что посмотреть

1. Открой [README](../../README.md) и [английский отчёт](../report/en/Tappix-Pre-Defense-Report-EN.pdf).
2. Проверь тему, своё имя, обязанности и сроки. Подготовка Армата с ИИ не должна
   выдаваться за твою самостоятельную работу.
3. Посмотри [схемы](../../diagrams/README.md): объясни своими словами путь запроса,
   роль Go, PostgreSQL и Redis, разделение компаний и хранение баланса через ledger.
4. Пройди [макеты](../prototype/README.md): карта → визит → доступная награда →
   отдельная выдача; показатели владельца и назначение пробного доступа.
5. Проверь [критерии](../report/submission-checklist.md). Интервью и отзыв руководителя
   пока не получены; зелёный CI не означает, что новое приложение уже работает.

Непонятный момент — повод задать вопрос в PR, а не скрыть его.

## Где оставить отзыв

Открой PR и вкладку **Files changed**. Проверяй по порядку:

| PR | Содержание |
| --- | --- |
| [#1](https://github.com/islqdev/tappix-diploma/pull/1) | README, требования, ответственность и правила |
| [#2](https://github.com/islqdev/tappix-diploma/pull/2) | CI и границы его проверок |
| [#3](https://github.com/islqdev/tappix-diploma/pull/3) | Источники, сравнения и ограничения выводов |
| [#4](https://github.com/islqdev/tappix-diploma/pull/4) | Роли и архитектурные схемы |
| [#5](https://github.com/islqdev/tappix-diploma/pull/5) | Старый прототип; новая версия заменяет его в PR #6 |
| [#6](https://github.com/islqdev/tappix-diploma/pull/6) | Английский отчёт, новые макеты, приложения и разрешённые PDF/Word |

Нажми **Review changes**, напиши своими словами, что проверил и какие вопросы
остались. **Comment** — вопрос; **Request changes** — нужно исправление;
**Approve** — проверено, препятствий к принятию нет. Затем **Submit review**.

Не копируй заявление о проверке, которой не было. Merge самостоятельно не нужен:
после одобрения изменения принимаются по порядку с проверкой CI и зависимостей.
Новые изменения после ревью могут потребовать повторного просмотра.

## Необязательная локальная проверка

Нужны Git и Node.js 22. Из уже клонированной папки этого репозитория:

```sh
git fetch origin
git switch DIP-14-pre-defense-report
git pull --ff-only
node --check tests/repository.test.mjs
node --test tests/repository.test.mjs
```

Сначала сохрани свои незакоммиченные изменения; не используй reset или очистку.
Эти команды не подключаются к базе старого Tappix. Напиши в отзыве, выполнял
ли команды или только читал материалы.
